# LINKUP 16.10.1 — LvlUp Demo Redirect Fix (2026-10-27)

Fixes `/app/lvlup` bouncing to `/app/linky` instead of rendering the investor demo.

## Root cause
The signed-out web guard in `mobile/App.tsx` rewrites any URL outside its
allowlist (`''`, `/`, `/landing`, `/login`, `/profile/*`, `/opportunity/*`) to
`/app/landing` via `history.replaceState`. `/lvlup` was missing, so:
1. Cold load of `/app/lvlup` briefly resolved `LvlupDemo`, then the guard
   rewrote the URL to `/app/landing`.
2. When auth resolved, `navigationStateKey` (`guest-…` → `<uid>-…`) remounted
   the `NavigationContainer`, which re-parsed the (rewritten) URL.
3. `Landing` doesn't exist in the signed-in stack, so navigation fell back to
   the initial route `Main` → `initialRouteName="LinkyHome"` → `/app/linky`.

Signed-out visitors were equally broken (remount lands them on `Landing`).

## Fix
- `mobile/App.tsx`: added `/lvlup` to the guard's `publicPaths` set (one line).
  The URL now survives untouched, so both the pre-auth flash and the post-auth
  remount resolve `LvlupDemo` (mounted in both stacks since 16.10.0).
- `tests/lvlup-demo.test.mjs`: new regression test (7th) asserting `/lvlup` is
  in `publicPaths`, the linking map has `LvlupDemo: 'lvlup'`, and both stacks
  mount the screen. Verified it fails with the fix reverted, passes with it.
