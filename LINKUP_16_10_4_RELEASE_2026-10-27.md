# LINKUP 16.10.4 — LvlUp Crash Fix: Stale API Shapes (2026-10-27)

Fixes the `/app/lvlup` white-screen crash:
`TypeError: Cannot read properties of undefined (reading 'length')`.

## Root cause
16.10.3 added `why[]`/`lane` to the lvlup API cards and the client reads
`pick.why.length` unguarded. But the API is CDN-cached (`s-maxage=300` +
`stale-while-revalidate=3600`), so right after deploy the NEW client can
receive an OLD cached JSON shape with no `why`/`lane` — instant crash inside
`picks.map → renderPick`. The stack trace matches exactly.

## Fix (`mobile/src/screens/LvlupDemoScreen.tsx` only)
- `why`/`lane`/`laneWhy` are now optional in `LvlupPick` (old cached shapes
  are a fact of life, the type admits it).
- `renderPick` normalizes: `Array.isArray(pick.why) ? pick.why : []`; the
  why-block renders from the normalized array.
- Lane pill row + digest lane suffix render only when `lane` exists.
- Worst case on a stale response is now "cards without why-bullets for a few
  minutes", never a crash.

- Local: typecheck clean; seo 51/51, copy 8/8, builder 56/56 (server/texts
  untouched — client-only fix).
- Live check after deploy: hard-refresh `/app/lvlup` — page renders even
